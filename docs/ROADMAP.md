# Roadmap

Roadmap 用来描述阶段目标，不作为承诺日期。README 只链接当前 Roadmap，不展开所有路线细节。

## v0.5：产品与文档收敛

目标：理清产品定位、文档职责和核心主线。

- 明确目标用户：项目创建者本人、学生、个人知识工作者。
- 明确主线：收集箱自动整理 + Markdown Vault + RAG 文件问答。
- 修正 AI 自动移动边界：允许在受控 Vault 范围内自动移动收集箱文件。
- 新增 PRD、交付物关系、架构、路线图和同类项目调研文档。
- 明确概念图只是灵感参考，不是硬性还原标准。
- 清理 README，避免把未实现能力描述为已完成。
- 明确 Markdown/YAML-first：用户可读事实优先写入 Markdown，SQLite 只承担索引、日志、队列、Trace、预算和缓存等内部状态。
- 明确个人页和项目工作台已接入 Workspace Insights 第一版真实统计；正式 TODO/日程已有 SQLite 第一增量，学习曲线、项目级 Agent 历史、联系人档案和项目级任务增强仍是后续目标。
- 标注前端真实可用、实验、占位、后续目标和 fallback 的区别。

## v0.6：可信收集箱自动整理

目标：把 `000-收集箱` 做成第一核心体验。

- 后台队列消费：第一层手动 drain worker 和应用内 resident worker 第一版已接入；resident worker 由用户手动启动/停止，默认 5 秒 tick、单并发、每 tick 最多处理 1 条队列项。
- 明确后台 worker：已实现从队列取任务、稳定等待、调用 MiMo、检查预算、执行移动、写审计、基础重试、失败/冲突单项恢复、批量恢复预览/确认、回滚衔接和应用内常驻消费循环；系统服务/托盘生命周期、应用启动自启、完整去重与更细恢复策略仍待增强。
- 文件监听：收集箱递归监听、递归扫描与自动入队第一版已接入，长时间实机稳定性仍待验证。
- 动态归档模板 / Archive Map：第一版已接入。当前会扫描正式 Vault 目录结构、生成 `.thebrain/rules/archive-map.md`、缓存目录索引、历史引用和本地启发式目录语义摘要，并让手动“生成计划”和后台 worker 共用这份目标目录上下文；只读健康检查、失效目录提示、基于 movement log 的历史归档命中排行、用户目录说明/锁定规则第一增量，以及 Archive Map 命中/新目录建议/确认原因元数据第一增量已接入。后续仍需更强 AI/长期语义总结、规则生命周期与批量编辑、长期趋势可视化和更完整的新目录确认交互。
- 自动抽取、自动分类、自动移动：已具备可信非 mock 决策下的第一层能力；当前已接入 Archive Map，并能把新目录建议、低置信度、目标冲突、收集箱内目标和分类边界不清写入结构化确认原因。下一步需要继续增强确认 UI、批量处理和更细的恢复体验。
- 冲突策略：已接入 conflict 列表、冲突详情、只读重命名建议、bounded preview、bounded 只读 diff、用户答案记录、Markdown 规则记忆、SQLite 规则索引/命中、规则启用/禁用/编辑和确认后应用；不自动覆盖、不静默删除。
- 冲突问答窗口：第一版已在收集箱侧栏提供可见入口、动作选择和只读 diff 预览；后续仍需更完整的 side-by-side/merge diff 体验、批量冲突处理、强确认的重命名/覆盖执行流和更完整的恢复体验。
- 批量整理：需要在 Archive Map、预算、冲突规则和批量恢复策略明确后增强。
- 可见 audit 和 movement log：movement log 列表、单项/批量回滚预览、最近 audit timeline、audit 文本搜索、类型筛选、日期范围筛选、分页加载和详情展开已接入收集箱状态区域；长期审计分析、更细时间线视图和跨事件聚合仍待增强。
- 回滚体验：基础回滚命令、movement log 单项回滚、批量回滚只读预览和确认入口已存在；冲突恢复体验、更完整差异预览和批量确认策略仍待增强。
- UI 清楚展示整理状态、失败原因和恢复动作：收集箱状态面板第一版已接入，集中展示 listener、queue、worker、resident worker、conflict、Archive Map 健康、movement log、audit timeline、最近事件和最近错误，并支持常驻 worker 手动启动/停止、整理计划确认原因展示、audit 日期范围/分页/详情、队列单项恢复、队列批量重试/跳过预览确认、movement log 单项回滚和批量回滚预览确认。
- 将 `src/App.tsx` 中不相关的页面和占位数据逐步拆成组件与状态模块，减少主入口复杂度。

## v0.7：本地 RAG 与 NotebookLM 式问答

目标：让用户能对整理后的 Vault 进行有引用的问答。

- 真实 embedding。
- 向量检索。
- rerank。
- 多轮会话 UI 第一版已完成；会话重命名、删除、按标题/消息历史搜索和当前回答引用筛选第一增量已接入，后续增强引用排序/固定。
- 历史会话列表第一版已完成，后续增强删除恢复/归档策略和更完整的长期记忆策略。
- 按范围问答：全 Vault、当前文件、当前项目、选中文件。
- 引用打开和定位。
- 上下文不足时的明确 fallback。

v0.7 是阶段化里程碑，不是产品终点。README 和 PRD 中的完整愿景会继续拆到 v0.8、v0.9、v1.0 和后续版本，不要求在 v0.7 一次性完成所有长期目标。

## v0.8：TODO、日程与个人档案

目标：从笔记、会议纪要、通话记录和便利贴中抽取行动与人际关系信息。

- TODO 候选到正式 TODO：第一增量已接入，候选可幂等 promotion 为 SQLite 内部 `todo_items`，并支持列表、完成和取消。
- 日程候选到正式日程：第一增量已接入，候选可幂等 promotion 为 SQLite 内部 `schedule_items`，并支持列表、完成和取消。
- TODO/日程增强：正式行动项前端搜索过滤和 Markdown 来源定位第一增量已接入；后续仍需提醒通知、重复日程、优先级、批量确认、后端分页/全文搜索、非 Markdown 来源定位、Markdown/YAML 双写或重建策略。
- 人名档案。
- 联系方式、地址、备注、来源记录。
- 会议纪要和通话记录结构化。
- 来源引用和隐私边界。
- 默认遵守 Markdown/YAML-first：人物、项目、会议和长期档案优先形成可读 Markdown；提醒、排序、命中统计和内部状态再进入 SQLite。

## v0.9：便利贴与低摩擦捕获

目标：让灵感和临时内容能快速进入 TheBrain。

- 独立多窗口便利贴。
- 托盘体验。
- 全局快捷键。
- 自动保存。
- 自动进入收集箱。
- 可被 AI 整理。

## v1.0：开源可用版本

目标：面向更多用户发布稳定版本。

- Windows 实机长期验证。
- 安装包。
- 示例 Vault。
- 基础文档和贡献指南。
- 更稳定的凭据和设置体验。
- 清晰的已支持/实验/路线图能力分层。

## 暂不优先

- 企业多用户权限。
- 云端协作。
- 完整对象数据库替代 Markdown。
- 类 Notion/AFFiNE 的 block/canvas 全量系统。
- 全模型、全向量库、全格式一次性接入。
