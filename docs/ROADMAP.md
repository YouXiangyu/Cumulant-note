# Roadmap

Roadmap 用来描述阶段目标，不作为承诺日期。README 只链接当前 Roadmap，不展开所有路线细节。

## v0.5：产品与文档收敛

目标：理清产品定位、文档职责和核心主线。

- 明确目标用户：项目创建者本人、学生、个人知识工作者。
- 明确主线：收集箱自动整理 + Markdown Vault + RAG 文件问答。
- 修正 AI 自动移动边界：允许在受控 Vault 范围内自动移动收集箱文件。
- 新增 PRD、交付物关系、架构、路线图和同类项目调研文档。
- 明确概念图只是灵感参考，不是硬性还原标准。
- 清理 README，避免把未实现能力描述为已完成。
- 明确 Markdown/YAML-first：用户可读事实优先写入 Markdown，SQLite 只承担索引、日志、队列、Trace、预算和缓存等内部状态。
- 明确个人页和项目工作台可以先按设计图保留为前端概念页，暂不要求接入正式后端数据。
- 标注前端真实可用、实验、占位、后续目标和 fallback 的区别。

## v0.6：可信收集箱自动整理

目标：把 `000-收集箱` 做成第一核心体验。

- 后台队列消费：第一层手动 drain worker 已接入，长期常驻 worker 仍待实现。
- 明确后台 worker：已实现从队列取任务、稳定等待、调用 MiMo、检查预算、执行移动、写审计、基础重试和回滚衔接；完整去重与恢复策略仍待增强。
- 文件监听长期稳定性。
- 自动抽取、自动分类、自动移动：已具备可信非 mock 决策下的第一层能力。
- 冲突策略：当前只记录 conflict，不自动重命名、不覆盖。
- 冲突问答窗口：遇到分类、命名或目标路径冲突时询问用户，并把用户回答沉淀为可复用整理规则。
- 批量整理。
- 可见 audit 和 movement log：基础命令与记录已存在，面向冲突处理的完整 UI 仍待增强。
- 回滚体验：基础回滚命令已存在，批量和冲突恢复体验仍待增强。
- UI 清楚展示整理状态、失败原因和恢复动作：worker 状态、最近运行结果和队列状态已接入，恢复动作仍待细化。
- 将 `src/App.tsx` 中不相关的页面和占位数据逐步拆成组件与状态模块，减少主入口复杂度。

## v0.7：本地 RAG 与 NotebookLM 式问答

目标：让用户能对整理后的 Vault 进行有引用的问答。

- 真实 embedding。
- 向量检索。
- rerank。
- 多轮会话 UI。
- 历史会话列表。
- 按范围问答：全 Vault、当前文件、当前项目、选中文件。
- 引用打开和定位。
- 上下文不足时的明确 fallback。

v0.7 是阶段化里程碑，不是产品终点。README 和 PRD 中的完整愿景会继续拆到 v0.8、v0.9、v1.0 和后续版本，不要求在 v0.7 一次性完成所有长期目标。

## v0.8：TODO、日程与个人档案

目标：从笔记、会议纪要、通话记录和便利贴中抽取行动与人际关系信息。

- TODO 候选到正式 TODO。
- 日程候选到正式日程。
- 人名档案。
- 联系方式、地址、备注、来源记录。
- 会议纪要和通话记录结构化。
- 来源引用和隐私边界。
- 默认遵守 Markdown/YAML-first：人物、项目、会议和长期档案优先形成可读 Markdown；提醒、排序、命中统计和内部状态再进入 SQLite。

## v0.9：便利贴与低摩擦捕获

目标：让灵感和临时内容能快速进入 TheBrain。

- 独立多窗口便利贴。
- 托盘体验。
- 全局快捷键。
- 自动保存。
- 自动进入收集箱。
- 可被 AI 整理。

## v1.0：开源可用版本

目标：面向更多用户发布稳定版本。

- Windows 实机长期验证。
- 安装包。
- 示例 Vault。
- 基础文档和贡献指南。
- 更稳定的凭据和设置体验。
- 清晰的已支持/实验/路线图能力分层。

## 暂不优先

- 企业多用户权限。
- 云端协作。
- 完整对象数据库替代 Markdown。
- 类 Notion/AFFiNE 的 block/canvas 全量系统。
- 全模型、全向量库、全格式一次性接入。
