# TheBrain PRD

## 1. 产品愿景

TheBrain 是一个本地优先的个人外置大脑。它帮助用户把学习、生活、项目、人际关系和长期资料放入一个可整理、可检索、可问答、可回滚的本地知识系统。

它不是单纯的笔记软件，也不是单纯的聊天机器人。它以本地 Markdown Vault 为基础，用 AI 帮用户自动整理、提取行动项、建立档案，并对整理后的资料进行带引用的问答。

## 2. 目标用户

第一目标用户：

- 项目创建者本人。
- 学生用户：课程资料、考试复习、作业、项目、会议和生活信息需要长期整理的人。

第二目标用户：

- 知识工作者。
- 开发者和研究者。
- 需要管理项目资料、人际关系、会议纪要和长期记忆的个人用户。

未来目标：

- 开源给更广泛的个人知识管理用户，允许不同用户根据自己的整理范式扩展。

## 3. 产品定位

TheBrain 的组合定位：

- Obsidian 增强版：本地 Markdown Vault、目录、标签、双链和可编辑文件。
- NotebookLM 增强版：对本地资料进行引用式问答、总结、对比和行动建议。
- 滴答清单补充：从笔记和记录中提取 TODO、日程和提醒。
- 个人第二大脑：管理学习、生活、人际关系、项目和长期档案。

### 3.1 数据组织原则

TheBrain 采用 Markdown/YAML-first，而不是数据库-first。

- 用户主要资产应优先落在本地 Markdown、YAML frontmatter、目录结构、wikilink 和可读文本文件中，保证接近 Obsidian 的本地文件管理理念。
- YAML frontmatter 只保存标题、标签、来源、状态、分类号、创建/更新时间等小型元数据。
- 双向链接、知识图谱、收集箱历史映射、项目/人物/资料之间的显性关系，应优先用 Markdown 链接、列表和可读 ledger 表达。
- SQLite 主要用于 Markdown 难以高效表达或不适合污染用户笔记的数据，例如索引、embedding、队列、移动日志、审计日志、预算账本、Trace、命中统计和缓存。
- 当 Markdown 与 SQLite 同时记录同一类事实时，需要明确主从关系；面向用户可阅读和迁移的事实优先以 Markdown 为主。

### 3.2 能力状态约定

为了允许前端先按完整产品愿景建设，同时避免误导用户，所有能力需要区分状态：

- 真实可用：已有明确的前端入口、Tauri command、本地服务、Vault 或 SQLite 数据支撑。
- fallback：后端命令失败或运行环境不完整时的安全降级结果，必须携带原因，不代表能力已完成。
- 占位：按设计图或产品愿景保留的 UI 与样例数据，暂不接正式后端。
- 后续目标：已进入 PRD/Roadmap，但当前阶段不要求实现。

未完成能力可以在 UI 中出现，但代码、README 和 PRD 必须清楚标注状态；当后端能力真实接入后，应删除对应占位数据和占位说明。

## 4. 核心工作流

### 4.1 收集箱与 AI 自动整理

用户把文件、文字、图片、录音或临时内容放入 `000-收集箱/`。

TheBrain 自动执行：

1. 识别新内容。
2. 抽取文本或结构化信息。
3. 扫描 Vault 中可作为正式归档位置的目录结构，生成动态归档模板 / Archive Map。
4. 基于内容和 Archive Map 判断内容类型、主题、来源、标签、目标目录。
5. 将文件移动到合适位置。
6. 更新 `收集箱-已整理.md`、movement log 和 audit events。
7. 在需要时生成 TODO、日程、联系人档案或后续行动候选。

AI 自动移动只允许发生在受控 Vault 范围内，且只处理 `000-收集箱/` 中允许处理的文件。

动态归档模板 / Archive Map 是收集箱自动整理的核心上下文，不应是固定的前端模板，也不应让 AI 凭空猜测目标路径。TheBrain 应根据用户当前 Vault 的真实目录结构生成 Archive Map，并在生成整理计划和 worker 自动整理时传给 MiMo。Archive Map 至少应包含：可用目标目录、目录层级、代表性文件名、常见主题或分类线索，以及用户已经形成的归档习惯。

Archive Map 必须遵守以下规则：
- 默认扫描正式 Vault 目录，排除 `.thebrain/`、`.secrets/`、`.git/`、`node_modules/`、`target/`、`dist/` 等内部或工具目录。
- `000-收集箱/` 是待处理来源，不进入 Archive Map，也不是正式归档目标；其子目录结构不得作为归档目标或归档分类依据。需要历史参考时，只允许读取 `收集箱-已整理.md`、movement log 或 audit events 中的已完成移动记录。
- AI 生成目标路径时应优先选择 Archive Map 中已有目录。
- 当现有目录没有合适位置时，AI 可以建议新建目录，但必须说明原因；低置信度、新目录建议、命名冲突或分类边界不清时，应进入 conflict/确认流程。
- 手动“生成计划”和后台 worker 必须使用同一份 Archive Map，不能走两套整理逻辑。
- Archive Map 应有用户可读版本，例如 `.thebrain/rules/archive-map.md`；SQLite 可以缓存索引、更新时间和命中信息，但不应成为唯一可读来源。

当自动整理遇到命名、分类、语义边界或目标路径冲突时，应弹出类似 Codex question 的确认窗口，向用户清楚说明冲突点、候选方案和影响范围。用户的回答不只用于本次处理，还应被整理成可复用的规则或概念说明，保存到本地可读规则文件，并在 `.thebrain` 中记录命中、审计和索引状态，便于下一次遇到相似冲突时自动解决或优先推荐。

### 4.2 快速便利贴

用户可以通过快捷键快速打开便利贴，捕获灵感、临时想法、任务和碎片记录。

便利贴应尽量低摩擦：

- 快速打开。
- 自动保存。
- 可进入收集箱。
- 可被后续 AI 整理。

### 4.3 Markdown Vault

用户仍然可以像使用 Obsidian 一样直接读写 Markdown 文件。TheBrain 不应锁死用户数据，也不应把用户文件转成不可读数据库。

Markdown 文件承担：

- 用户可编辑内容。
- 标题、标签、来源、状态等轻量元数据。
- 双链和引用。

### 4.4 文件问答与长期记忆

TheBrain 对整理后的 Vault 建立本地索引。用户可以提问、总结、比较、提取行动项，并查看引用来源。

回答必须尽量做到：

- 有引用。
- 能打开来源文件。
- 能说明上下文不足或 fallback 原因。
- 不伪造已经完成的 AI 能力。

### 4.5 TODO、日程和个人档案

TheBrain 可以从会议纪要、通话记录、笔记和收集箱内容中提取：

- TODO。
- 日程。
- 人名档案。
- 联系方式。
- 地址和备注。
- 项目关系。
- 后续行动。

这些数据的最终写入方式需要后续设计，但默认遵守 Markdown/YAML-first：人物、项目、会议和长期档案等用户可读事实优先写入 Markdown；搜索、排序、提醒、去重、访问频率和内部审计等运行状态可进入 SQLite；必要时采用 Markdown + SQLite 双写，但必须定义主从关系。

### 4.6 个人页与项目工作台

个人页不是 GitHub 个人主页，而是 TheBrain 应用内的个人知识工作台入口。它面向学习进度、复习推荐、目标、TODO、灵感、个人档案和长期统计。项目工作台是应用内按 Vault 项目/目录聚合资料、对话、行动项和 Agent 历史的入口。

当前阶段允许个人页和项目工作台先按概念图或设计图保留完整前端布局，但不要求接入正式后端数据。它们应被定义为前端概念页或占位页：可以混合少量真实 Vault 计数与样例数据，但不能把学习曲线、Agent 历史、复杂统计、联系人档案等尚未实现能力描述为已完成。

## 5. 当前范围

v0.5 优先范围：

1. 清晰定义收集箱自动整理闭环。
2. 修正 README 和 AGENTS 中关于 AI 自动移动的边界。
3. 建立 PRD、交付物关系、架构和路线图文档。
4. 明确前端可展示未完成能力，但必须标注真实状态。
5. 保持 Markdown-first 和 local-first。
6. 明确个人页和项目工作台当前可作为前端概念页保留，后端能力逐步补齐。
7. 明确 v0.7 等版本号是阶段化里程碑，不代表长期目标只做到该阶段；README 和 PRD 中的完整愿景会在后续版本持续拆分实现。

## 6. 非目标

当前阶段不追求：

- 企业级多用户权限。
- 云端协作。
- 完整对象数据库替代 Markdown。
- 全模型、全向量库、全文件格式一次性接入。
- 类 Notion/AFFiNE 的 block/canvas 全量系统。
- 完整 Agent OS。

## 7. 产品原则

- 本地优先。
- 用户文件可读、可迁移、可脱离 TheBrain 使用。
- AI 可以自动处理，但必须可追溯、可回滚、可限制范围。
- 不覆盖用户已有文件。
- 不伪造 AI 成功。
- 前端可以展示愿景能力，但必须标注真实状态。
- 已实现功能应替换并删除对应占位实现，避免占位长期混入真实能力。
- README 描述当前事实，PRD 描述产品目标和边界，Roadmap 描述阶段计划。
